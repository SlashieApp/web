# Elevation

SDL ships a single elevation scale, `sdlElevation` (`e1`–`e5`), exported from
`@/theme/styles` and registered as Chakra `shadows` tokens in
`src/theme/chakraSystem.ts`. Reference elevation by token (`boxShadow="e3"`),
never as a raw `box-shadow` string in feature code. Chakra's own `xs/sm/md/lg/xl`
shadow names are its defaults, not aliases of `e1`–`e5`: use `e1`–`e5`.

A hairline first, then the least shadow that does the job, in ink at low alpha.
`e3` and `e4` carry their own 1px ring, so a surface that uses them has no border
of its own.

Every value below is read live from the theme modules, so this page cannot
drift from code.

export const LEVELS = Object.keys(sdlElevation)

export const USAGE = {
  e1: 'Cards at rest, with a 1px border.default hairline.',
  e2: 'Hover and raised cards, sticky bars, featured pricing.',
  e3: 'Floating chrome, menus, popovers, map overlays. A ring, no border.',
  e4: 'Drawers and sheets. A ring, no border.',
  e5: 'Dialogs.',
}

{/* Only e1 and e2 sit on a border: e3 and e4 draw their own ring, e5 is a lift. */}
export const WITH_BORDER = ['e1', 'e2']

export const ElevationCard = ({ level }) => (
  <Box
    bg="bg.surface"
    color="text.default"
    borderWidth={WITH_BORDER.includes(level) ? '1px' : 0}
    borderColor="border.default"
    borderRadius={`${sdlRadii.lg}px`}
    boxShadow={level}
    p={`${sdlSpace[5]}px`}
    transitionProperty="box-shadow, transform"
    transitionDuration={sdlMotion.duration.moderate}
    transitionTimingFunction={sdlMotion.easing.standard}
  >
    <Text fontWeight={500} fontSize="md">
      {level}
    </Text>
    <Text color="text.muted" fontSize="sm" mt={`${sdlSpace[1]}px`}>
      {USAGE[level]}
    </Text>
    <Text
      as="code"
      display="block"
      mt={`${sdlSpace[3]}px`}
      fontFamily="mono"
      fontSize="xs"
      color="text.subtle"
    >
      {sdlElevation[level]}
    </Text>
  </Box>
)

## Card recipe

Every card-shaped surface uses `sdlCard` from `@/theme/styles`:

| Role | Radius | Shadow | Examples |
| --- | --- | --- | --- |
| Rest | `lg` | `e1` | Task cards, auth form cards, dashboard sections |
| Raised | `lg` | `e2` | Hover, selected, featured plan |
| Overlay | `lg` | `e3` (a ring, no border) | Map empty state, browse filters, search-this-area |

`<Card>` applies the rest recipe. Feature `Box` shells should spread `sdlCardSurface` or `sdlOverlaySurface` instead of inventing a second radius. `sdlOverlaySurface` has no border, because `e3` carries its own ring.

## Dark mode: prefer border over heavy shadow

`sdlElevation` shadows are tuned for the light canvas (a low-alpha ink shadow on
white). On the dark canvas a soft shadow against a dark surface reads as muddy,
so dark mode communicates depth primarily through a **raised surface color plus
a 1px border**, not a heavy drop shadow:

- Step the surface up the `bg` ramp (`bg.canvas` → `bg.surface` → `bg.raised`)
  rather than increasing shadow weight.
- Keep a `1px` `border.default` (or `border.strong` for the top layer) so edges
  stay crisp without relying on the shadow.
- It is fine to keep the same `boxShadow` token in both modes — it simply does
  less visual work in dark, where the border and surface carry the elevation.

Notice in the comparison above how each card stays legible in dark via its
border and surface, while in light the shadow does most of the lifting.

## Motion

Animate elevation changes with `sdlMotion` (from `@/theme/styles`) and only ever
animate `transform`/`opacity`/`box-shadow` — never layout properties. The cards
above transition over `{sdlMotion.duration.moderate}` using the
`standard` easing curve (`{sdlMotion.easing.standard}`).
